1.  Description of the Web Application 
For my project, I'm going to build a Workout/Exercise Logger web application. The idea is to 
help users plan their workouts, track their exercise routines, and keep an eye on their fitness 
progress. 
The main functionality will include adding, viewing, editing, marking as complete, and deleting 
workout entries. Each workout entry will have these attributes: 
●  Exercise Name: A short description of the workout (like "Morning Run," "Chest Day," or 
"Yoga Session").  
●  Description: More details about the workout - things like distance, reps, sets, duration, or 
any notes I want to remember (this one's optional).  
●  Due Date: When I'm planning to do the workout.  
●  Status: Where the workout is at right now - either "Planned," "In Progress," or 
"Completed."  
●  Priority: How important the workout is for my fitness goals - "Low," "Medium," or 
"High."  
My Workout/Exercise Logger will let users: 
●  See all their workouts in a list. 
●  Add new workouts to their schedule. 
●  Edit workout details like the name, description, due date, and status. 
●  Mark workouts as completed when they're done. 
●  Delete workouts they don't need anymore. 
●  Filter workouts by status or priority.

3.  Web Framework, Database, and Version Control System 
For my web application, I'm planning to use the following technologies: 
●  Web Framework:  
○  Spring Boot (Backend): I chose Spring Boot for the backend because it's pretty 
straightforward to set up and has a lot of built-in features. It'll handle all the 
server-side stuff like processing requests, managing the business logic, and 
talking to the database. Plus it makes creating REST APIs really easy.  
○  React (Frontend): For the frontend, I'm using React because it makes building 
interactive user interfaces easier. I can create reusable components and manage 
the app's state without too much hassle. React will handle displaying the workouts 
and sending requests to the Spring Boot backend.  
●  Database:  
○  SQLite: I went with SQLite because it's simple to set up and doesn't need a 
separate database server running. Everything is stored in one file, which makes it 
perfect for this kind of project. Spring Boot works well with SQLite through JPA 
and Hibernate, so I can interact with the database using Java objects instead of 
writing a bunch of SQL queries. 
●  Version Control System:  
○  GitHub: I'll be using GitHub to keep track of my code and any changes I make. 
It's also a good backup in case something goes wrong. I might organize it as one 
repository with separate folders for the backend and frontend, or possibly two 
separate repos depending on how it goes. 
The way this will work is that React (the frontend) will talk to Spring Boot (the backend) using 
REST API calls. Spring Boot will then handle all the database operations with SQLite to save 
and retrieve workout information.

○  I'll package the Spring Boot backend as a JAR file and run it on the E2 instance.

server. 
○  I'll also need to set up the firewall rules on Google Cloud to allow web traffic to 
reach the application.
